# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

The Vault is a personal media catalog — browse, filter, and search 3,300+ movies, TV shows, documentaries, and standup specials. Pure static site: no build step, no server, no package.json. Part of the `punkrockprogramming` multi-repo workspace (see root `CLAUDE.md`), deployed standalone via git subtree.

## Running

Open `index.html` directly in a browser (`file://`) or serve it from any static server. There is no build/install step.

AI features (chat recommendations) are gated to local use only — `AI_ENABLED` in `app.js` checks for `localhost`, `127.0.0.1`, or `file:` protocol and hides them otherwise.

## Testing changes

No test suite. Syntax-check the two hand-written JS files after edits:

```bash
node --check app.js
node --check library.js
```

For anything touching the enrichment pipeline, spot-check `metadata.js` still parses:

```bash
node -e "require('vm').runInNewContext(require('fs').readFileSync('metadata.js','utf8').replace(/^const /gm,'var '), {})"
```

## Architecture

Four data/logic files loaded in a fixed order from `index.html`, as three browser globals plus one entry point:

```
metadata.js  → const METADATA   (generated, ~1.4MB, do not hand-edit)
library.js   → const RAW, GENRE_KW, GENRE_OVERRIDES
wiz-watched.js → const WIZ_FILMS  (gitignored, regenerated externally — empty array in this checkout)
app.js       → everything else
```

`app.js` builds the in-memory `ALL` array at load time by merging `RAW` (title/category) with `METADATA` (TMDB genres/description/poster) and falling back to `GENRE_OVERRIDES` or keyword-matching against `GENRE_KW` when a title has no TMDB match. This merge happens once, synchronously, at the top of `app.js` — there's no re-merge step, so any edit to `library.js` categorization or `metadata.js` genres just works on next page load.

**`library.js`** is the source catalog: `RAW` is keyed by category (`movies`, `tv`, `standup`, `docs`, `musicdocs`) with titles formatted as `"Title (Year)"`. `GENRE_KW` is a keyword-match fallback table (genre → substrings to match against the lowercased title) used when TMDB enrichment found nothing or missed the genre; `GENRE_OVERRIDES` is a per-title genre list that takes precedence over both TMDB and keyword matching.

**`metadata.js`** is TMDB-derived enrichment (`genres`, `description`, `poster`), keyed by the exact title string from `RAW`. It's generated by `enrich.mjs` — never hand-edit it. Re-running `enrich.mjs` resumes from existing entries (skips titles already present) and checkpoints to disk every 100 titles, so it's safe to interrupt.

**`wiz-watched.js`** is an external integration point: `wiz dashboard` (in the sibling `wiz/` project) regenerates this file with `WIZ_FILMS` — a watch log pulled from `~/.wiz-films/`. It's gitignored and gets matched to catalog titles by slugified string comparison. The deployed GitHub Pages site 404s this script harmlessly since it's local-only.

**`app.js`** owns all state and rendering: filter/sort state (`activeMoods`, `activeTypes`, `activeGenres`, `sortMode`, `statusFilter`), watched/want-to-watch status and per-title notes/ratings persisted to `localStorage` (`vault_status`, `vault_meta`, `vault_ai_conv` keys), grid/list rendering, the modal detail view, and the AI chat panel.

**AI chat** (`sendAIMessage` in `app.js`) posts directly from the browser to `https://api.anthropic.com/v1/messages` with no API key header attached in this file — auth is expected to come from something outside this repo (a local proxy or extension intercepting the request). If you're debugging "AI unavailable" locally, that's the first thing to check, not the app code.

## Enrichment pipeline

`enrich.mjs` is a one-time/resumable Node script, not part of the running app. It reads `TMDB_API_KEY` from `.env`, loads `RAW` out of `library.js` via a `vm` sandbox (translating `const` → `var` since `library.js` is a plain browser script, not a module), queries TMDB search for each title, and writes the result to `metadata.js`. Run it after adding new titles to `library.js`:

```bash
node enrich.mjs
```

Only titles missing from `metadata.js` are processed; to retry a title that came back with empty genres/description, delete its key from `metadata.js` first.

## Deployment

Static site, no CI build — `.github/workflows/deploy.yml` just uploads the repo root as-is to GitHub Pages on push to `main`. In the actual workspace this directory is a subtree of the `punkrockprogramming` monorepo pushed to its own GitHub repo:

```bash
git subtree push --prefix=the-vault the-vault main
```
